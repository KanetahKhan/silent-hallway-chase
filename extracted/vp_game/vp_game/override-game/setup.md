# Setup — OVERRIDE

This is the single source of truth for getting **OVERRIDE** running from a fresh
clone. Follow it top to bottom; no prior knowledge of the project is assumed.

The repo has two independent Maven modules:

| Module     | Path        | What it is                                  | How you run it          |
|------------|-------------|---------------------------------------------|-------------------------|
| Frontend   | repo root   | JavaFX desktop game                         | `mvn javafx:run`        |
| Backend    | `backend/`  | Spring Boot REST API (auth, saves, scores)  | `mvn spring-boot:run`   |

You can run the **frontend on its own** — it saves locally and needs nothing
else. The backend is only required for online accounts, cloud saves, and the
leaderboard.

---

## 1. Prerequisites

Install these first. Versions below are what the project is built and tested
against.

| Tool       | Version            | Notes                                                        |
|------------|--------------------|--------------------------------------------------------------|
| **JDK**    | **26**             | Frontend compiles to release 26. One JDK 26 builds both modules. |
| **Maven**  | **3.9+** (3.9.15)  | Build tool for both modules.                                  |
| **Git**    | any recent         | To clone.                                                    |
| JavaFX     | 26.0.1             | **Auto-downloaded by Maven** — no separate SDK to install.   |
| Database   | none for dev       | Backend uses an embedded, file-based **H2** DB (auto-created). MySQL 8+ is optional for production. |

Verify the toolchain:

```bash
java -version    # should report 26.x
mvn -version     # should report 3.9.x and pick up Java 26
```

> **Windows:** if `mvn` is not found, add Maven's `bin` folder to your `Path`
> (see [Troubleshooting](#8-troubleshooting)).

## 3. Environment

The **frontend needs no environment variables.**

For **local development the backend needs none either** — `application.properties`
ships with safe defaults (embedded H2, a dev-only JWT secret), so it runs out of
the box. The variables below only **override** those defaults and are
**required for any shared or production deployment** (never ship the dev secret).

| Variable | Required? | Example | What it's for |
|---|---|---|---|
| `APP_JWT_SECRET` | Prod | `a-random-256-bit-string…` | Signing key for auth tokens (≥ 32 chars / 256 bits). |
| `APP_JWT_EXPIRATION_MS` | No | `86400000` | Token lifetime in ms (default 24h). |
| `MYSQL_URL` | MySQL only | `jdbc:mysql://localhost:3306/override_db` | JDBC URL, if you switch from H2 to MySQL. |
| `MYSQL_USER` | MySQL only | `root` | MySQL username. |
| `MYSQL_PASSWORD` | MySQL only | `s3cret` | MySQL password. |

**Set them up:**

1. Copy the template and edit your values (`.env` is git-ignored — never commit it):
   ```bash
   cp .env.example .env
   ```
2. Spring Boot does **not** read `.env` automatically. Load it into your
   environment before starting the backend:

   **Windows (PowerShell):**
   ```powershell
   Get-Content .env | Where-Object { $_ -match '^\s*[^#].*=' } | ForEach-Object {
     $name, $value = $_ -split '=', 2
     Set-Item -Path "env:$($name.Trim())" -Value $value.Trim().Trim('"', "'")
   }
   ```

   **macOS/Linux (bash/zsh):**
   ```bash
   set -a; . ./.env; set +a
   ```

   Then start the backend in the same terminal (see [Run](#6-run)).

## 4. Install

Maven downloads all dependencies (including JavaFX) on the first build. Pre-fetch
them so the first run is fast and to confirm your toolchain works:

```bash
# Frontend (run from repo root)
mvn -q -DskipTests compile

# Backend
mvn -q -DskipTests -f backend/pom.xml compile
```

The first run needs internet access; subsequent runs are offline-capable.

---

## 5. Database / config

For local development there is **nothing to set up** — the backend uses an
embedded H2 database stored as a file at `backend/data/override-db.mv.db`. It is
created automatically on first start, and the schema is generated by JPA
(`spring.jpa.hibernate.ddl-auto=update`).

- **H2 console:** with the backend running, open <http://localhost:8080/h2>
  (JDBC URL `jdbc:h2:file:./data/override-db`, user `sa`, empty password).
- **Reference schema:** `backend/src/main/resources/db/schema.sql` documents the
  tables for MySQL/PostgreSQL. H2 does not need it (JPA auto-DDL handles it).
  This includes `high_scores` (one row per mini-game; see [Mini-Games](#mini-games))
  and `snake_high_scores` (single-row global best for Syntax Snake).
- **MySQL (production):** uncomment the MySQL block in `application.properties`
  and supply credentials via environment (see [Environment](#3-environment)).

## 6. Run

The two modules run in **separate terminals**.

### Frontend (the game)

```bash
# from repo root
mvn javafx:run
```

The game window launches. Maven fetches JavaFX automatically on the first run.

### Backend (REST API)

```bash
cd backend
mvn spring-boot:run
```

Starts on <http://localhost:8080>. Endpoints:

| Method | Endpoint                       | Auth | Description                       |
|--------|--------------------------------|------|-----------------------------------|
| POST   | `/api/auth/register`           | No   | Register (username, email, password) |
| POST   | `/api/auth/login`              | No   | Login → returns JWT               |
| GET    | `/api/player/me`               | Yes  | Current player profile + stats    |
| PUT    | `/api/player/update`           | Yes  | Update profile / stats            |
| POST   | `/api/save`                    | Yes  | Save game state                   |
| GET    | `/api/save`                    | Yes  | Load saves for current user       |
| POST   | `/api/chapter{1..5}/progress/update` | Yes | Update per-chapter progress  |
| GET    | `/api/leaderboard`             | No   | Top leaderboard entries           |
| GET    | `/api/highscore/{gameType}`    | No   | Best run for a mini-game (e.g. `kernel-panic`) |
| POST   | `/api/highscore`               | No   | Submit a mini-game run (raises the stored best) |
| GET    | `/api/snake-highscore`         | No   | Best score for **Syntax Snake** (Ch1 mini-game #2) |
| POST   | `/api/snake-highscore`         | No   | Submit a Syntax Snake run `{"score":N}` (raises the stored best) |

## 8. Troubleshooting

| Symptom | Cause / Fix |
|---|---|
| `mvn: command not found` / not recognized | Maven isn't on `Path`. **Windows:** `[Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\path\to\apache-maven\bin", "User")`, then open a new terminal. **macOS/Linux:** add Maven's `bin` to `PATH` in your shell profile. |
| Build fails with `invalid target release: 26` or class-version errors | Wrong JDK. Run `java -version` and `mvn -version`; both must report Java 26. Set `JAVA_HOME` to your JDK 26 install. |
| `mvn javafx:run` can't download JavaFX / build hangs on first run | First build needs internet to fetch JavaFX 26.0.1 and other deps. Check your connection/proxy, then retry. |
| Backend fails: `Web server failed to start. Port 8080 was already in use` | Another process owns 8080. Stop it, or change `server.port` in `application.properties`. |
| Backend fails: H2 `Database may be already in use` | A previous backend run is still holding the H2 file. Stop the other process (only one backend instance at a time). |
| Game window doesn't appear but no error | JavaFX needs a desktop session — it cannot run on a headless/SSH-only server. |
| Mini-game is silent | No audio device (e.g. headless box). Sound is procedurally synthesized and self-disables on the first failure — gameplay is unaffected. |

## Mini-Games

Mini-games live in `com.override.game.minigames` (frontend). Each extends the
`MiniGame` base (a Canvas + 60fps `AnimationTimer` loop) and reports a
`MiniGameResult(won, score, xpEarned, dependencyUsed)` to the launching chapter.
**No additional dependencies** — rendering is JavaFX Canvas and sound is
synthesized at runtime with the JDK's `javax.sound` (no `javafx-media`, no assets).

### Kernel Panic (Chapter 1)

`KernelPanicGame` — a fast, combo-based reflex arcade game. Glitch tokens drop
four lanes; select a lane and apply the matching fix to zap the lowest token,
chaining a combo multiplier. SPACE is the **Astra Assist** EMP: a screen-clearing
relief that costs your combo and counts toward the global Dependency Meter.

Controls:

| Keys | Action |
|------|--------|
| `Q` `W` `E` `R` | Select lane 1–4 |
| `U` `I` `O` `P` | Apply fix `;` `==` `!` `++` (legend shown in-game) |
| `SPACE` | Astra Assist EMP (screen clear; resets combo, +1 dependency) |
| `ENTER` | Reboot / instant restart on the game-over screen |
| `ESC` | Exit (reports the result to the chapter) |

In the full game it is **Chapter 1 → Logic Lab** (mini-game #1; unlocks Snake).
Or run it standalone:

```bash
mvn javafx:run -Djavafx.mainClass=com.override.game.minigames.KernelPanicDemo
```

**Persisted high score.** The best score / combo / wave per game is stored by the
backend `HighScore` entity (table `high_scores`, one row per `gameType`) via
`HighScoreService` and the `/api/highscore` endpoints. The desktop game caches
the best locally in `~/.override/kernel-panic.properties` so the game-over screen
shows it instantly and works offline; it syncs to the backend best-effort when it
is running. No login required (the endpoints are public).

### Syntax Snake (Chapter 1)

`SnakeGame` — the second Chapter 1 mini-game (unlocks after Kernel Panic).
The snake is a blinking terminal **cursor**; food is scattered **knowledge bits**.
Eating ramps the speed smoothly toward a cap so the run stays playable while the
pressure grows; an endless score-chase with a one-key instant-retry on death.
The chapter beat is "cleared" the first time score hits **300**, but the run
continues so the player keeps chasing a new best.

`SPACE` is the **Astra Assist**: autopilot that greedily, *smoothly* steers the
cursor at the nearest knowledge bit (toggle, never a takeover — feels like
turning on cruise control). Using it any time during a run forfeits the
**Independence Bonus** (+500 score, +50 XP) and counts once toward the global
Dependency Meter.

Controls:

| Keys                       | Action |
|----------------------------|--------|
| `↑` `↓` `←` `→` / `W A S D` | Steer the cursor |
| `SPACE`                    | Toggle Astra Assist (smooth autopilot; forfeits Independence Bonus, +1 dependency on first toggle) |
| `ENTER`                    | Instant retry on the game-over screen |
| `ESC`                      | Exit (reports the result to the chapter) |

**Persisted high score.** The global best is stored by the backend `SnakeHighScore`
entity (table `snake_high_scores`, single row) via `SnakeHighScoreService` and
the `/api/snake-highscore` endpoints. The desktop game caches it locally at
`~/.override/syntax-snake.properties` so the game-over screen shows BEST instantly
and works offline; it syncs to the backend best-effort. No login required.
